# Как получить APK без Android Studio (с телефона)

В проект добавлен GitHub Actions workflow: `.github/workflows/build-apk.yml`.
Он запускается в облаке GitHub, устанавливает JDK 17 и Android SDK, получает Gradle 8.9, генерирует настоящий Gradle Wrapper и собирает APK.

## Шаги
1. Создайте аккаунт на GitHub, если его ещё нет: https://github.com
2. В браузере телефона откройте GitHub и нажмите **+ → New repository**.
3. Назовите репозиторий `BlockLauncher`, выберите **Public** или **Private**, затем **Create repository**.
4. В репозитории нажмите **Add file → Upload files**.
5. Распакуйте этот ZIP на телефоне и загрузите содержимое папки `BlockLauncher` (не сам ZIP). Важно сохранить папку `.github/workflows` и файл `build-apk.yml`. Если файловый менеджер скрывает `.github`, включите показ скрытых файлов.
6. Нажмите **Commit changes**.
7. Откройте вкладку **Actions** → workflow **Build BLOCK LAUNCHER APK** → последний запуск.
8. Дождитесь завершения. Зелёная галочка означает, что сборка прошла.
9. Внизу страницы запуска найдите **Artifacts** и скачайте `BLOCK-LAUNCHER-debug-APK`.
10. Распакуйте скачанный архив артефакта — внутри будет `app-debug.apk`. Откройте APK на телефоне и разрешите установку из этого источника, если Android спросит.

## Если сборка упала
Откройте запуск в Actions, раскройте красный шаг и скопируйте последние строки ошибки. По ним можно исправить проект. Сам факт запуска workflow ещё не означает, что APK собрался.

## Важно
- Android Studio на телефоне не требуется.
- Нужен интернет и аккаунт GitHub.
- GitHub Actions имеет ограничения использования бесплатных минут, особенно для приватных репозиториев.
- APK подписывается debug-ключом и предназначен для установки/тестирования, не для публикации в Google Play.
- Workflow генерирует настоящий `gradle-wrapper.jar` во время облачной сборки; фиктивный JAR в ZIP не добавляется.
